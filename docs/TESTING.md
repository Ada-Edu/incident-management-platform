# How the Document Field Extraction feature is tested

A real test pyramid — **generated by an AI writer, audited by an independent AI reviewer, tightened by both.** Current shape (all green):

```
        ▲  2 e2e         (+1 skipped frontend placeholder)
       ▲▲  8 integration
     ▲▲▲▲  49 unit
```

| Layer | Count | What it exercises | Model | DB / stack |
|-------|-------|-------------------|-------|------------|
| **Unit** | 49 | Pure logic: text extraction + guard rails, model-response parsing/mapping, prompt contract, persistence row shaping, fetch routing, workflow control-flow (stubbed activities) | mocked | mocked |
| **Integration** | 8 | The Temporal workflow + **real activities** wired together; persisted-row values, retries, gateway workflow-id idempotency, attachment-unchanged-on-failure | stubbed with recorded fixtures | **real Supabase** (time-skipping Temporal env) |
| **E2E** | 2 | The live path: upload → gateway → deployed worker → **real Bedrock** → Supabase; extraction *quality* (decoy rejection, role→party mapping) + measured **<30s latency** + a failure path | **real Bedrock** | real running stack |

Layout: `temporal/tests/{unit,integration,e2e}/`. Shared builders/fixtures in `temporal/tests/conftest.py`.

## Design principles
- **Behavioral assertions on real field VALUES**, not `not null` / status / shape checks.
- **A test that can't fail when the feature breaks is worse than no test** — vanity tests were pruned during the audit.
- The one live-model test grades against a **ground-truth document with a decoy** (a name present in prose that is *not* a party), so an echoing/hallucinating model fails rather than passes.

## Running the suite

The worker is Python; there's no host Python, so tests run in a container. Layers requiring external services skip cleanly when their env is absent.

```bash
# from incident-management-platform/temporal
# UNIT — no external services
docker run --rm -v "$PWD:/app" -w /app python:3.12-slim \
  sh -c "pip install -q -e '.[dev]' && python -m pytest tests/unit -q"

# INTEGRATION — needs the local Supabase (service-role key) + Temporal test server (auto-downloaded)
docker run --rm --add-host host.docker.internal:host-gateway \
  -e SUPABASE_URL=http://host.docker.internal:54321 -e SUPABASE_SERVICE_ROLE_KEY=<service-role> \
  -v "$PWD:/app" -w /app python:3.12-slim \
  sh -c "pip install -q -e '.[dev]' && python -m pytest tests/integration -q"

# E2E — needs the full docker stack up (worker + gateway + Supabase + Bedrock creds)
docker run --rm --add-host host.docker.internal:host-gateway \
  -e SUPABASE_URL=... -e SUPABASE_SERVICE_ROLE_KEY=... \
  -e RUN_E2E=1 -e E2E_GATEWAY_URL=http://host.docker.internal:8088 \
  -v "$PWD:/app" -w /app python:3.12-slim \
  sh -c "pip install -q -e '.[dev]' && python -m pytest tests/e2e -q"
```

Markers: `integration`, `e2e` (declared in `pyproject.toml`). E2E is gated behind `RUN_E2E=1`.

## What the independent audit changed
Full report: [TEST-REVIEW-REPORT.md](TEST-REVIEW-REPORT.md). Highlights:
- **Two product bugs found and fixed:**
  1. `extract_fields` crashed (retryable `AttributeError`) on a non-object model payload → now a non-retryable `model_error`.
  2. A model call that exhausted all retries left the row stuck `running` → the workflow now routes any terminal model-activity failure to `failed`/`model_error`.
- The e2e was rewritten from "assert strings that appear in the input" (passed for the wrong reason) to ground-truth + decoy grading with measured latency.
- Vanity/tautological prompt checks were replaced with contract assertions; guard-rail coverage extended to DOCX; idempotency, attachment-retention, and empty-but-valid extraction added.

## Known gaps (intentional)
- **Frontend rendering criteria are not covered by this backend suite:** "extracted fields shown *beside the source*" and the **"None found"** empty-group display. A `@pytest.mark.skip` placeholder in `tests/e2e/` documents the intended **Playwright** test (log in at `localhost:3000` → upload → assert the three headings + "None found" render beside the document). Tracked for the frontend/web-e2e suite.
- **Latency** is asserted end-to-end (<30s) but not as a statistical SLO (spec's "≥95% within 30s"); that belongs in monitoring, not a unit/integration test.

## Takeaway — AI-written tests vs. where a human eye is needed
- **Unit: largely AI-clean** — concrete value/guard-rail/mapping assertions out of the gate.
- **E2E and the "pass-for-wrong-reasons" class needed the independent review** — the original e2e passed against baked-in answers, and both product bugs surfaced only when a *fresh context* and per-layer agents attacked behavior rather than re-reading the original author's tests.
